

## Codebase Patterns
- **Domain = pure contracts, never PKHeX types**: `PKForge.Domain.csproj` has no ProjectReference to the engine. A "parsed PKHeX save" in Domain-speak is an open `ISaveEngineSession` (`EntityEditing.cs`) or the extracted records (`SaveSnapshot`, `DexProgress`, `TrainerStats` in `Contracts.cs`/`EntityEditing.cs`). Factories that need a save take those abstractions, so Domain tests never touch PKHeX.
- **Faking a huge interface in tests**: `ISaveEngineSession` has ~107 members — never hand-write a fake. Use `System.Reflection.DispatchProxy` (BCL, see `ExternalCompanionTests.SessionProxy`): configured members return values, everything else throws (which doubles as the "unreadable save" case).
- **Party vs boxes in a snapshot**: `SaveSnapshot.Slots` holds boxes at `Box >= 0` and the party at `Box == -1` (see `SaveEngineSession.BuildSnapshot`); party count = slots with `Box == -1 && Species > 0`, clamp to 6.
- **Playtime truth**: `TrainerStats.SupportsPlayTime` gates `PlayTimeHours/Minutes`; the shelf's `PlayTime` string is only a fallback (pattern in `TrophyScanService.TryParsePlaytime`).
- **Companion snapshot shape**: mirror `GameCompanion.cs` / `LiveGbaCompanion.cs` — flat record + `DexPercent` computed property (`DexTotal == 0 ? 0 : round(caught*100/total)`).
- **Persistence**: Infrastructure JSON stores write atomically (pattern in `JsonConsoleEmulatorStore`); reuse for any new persisted state.
- **Ralph loop mechanics**: branch name comes from `prd.json` `branchName`; one story per iteration = highest priority with `passes: false`; commit `feat: US-XXX - ...`; set `passes: true` + `notes` (manual device checks go in notes, never block); APPEND to `progress.txt`, never overwrite.
- **This sandbox has no .NET SDK**: validate via static checks locally, CI (`build` workflow on PR/push) runs `dotnet test` Release + the net10.0-android APK build. Wait for the PR check before merging.

## 2026-11-09 ~15:15 - US-001 (CI fixes)
- CI a révélé 3 pièges DispatchProxy, corrigés et maintenant documentés :
  1. `DispatchProxy.Create<T, TProxy>()` retourne T (l'interface) — caster via `(TProxy)(object)proxy`, pas directement (CS0030).
  2. La classe proxy ne peut PAS être `sealed` (ArgumentException « base type cannot be sealed »).
  3. Les propriétés arrivent à `Invoke` comme `get_Xxx` — normaliser `get_` avant de comparer à `nameof(...)`.
- **Apprentissage** : avec `TreatWarningsAsErrors=true`, initialiser les champs non-nullables du proxy (`= new(...)`) plutôt qu'un constructeur.
- Résultat : CI PR #6 verte (1032 Domain + 992 Engine tests, build APK OK), PR mergeable clean.

## 2026-11-19 ~16:20 - US-003
- Implémenté le cœur de décision **pur** dans le Domain (`src/PKForge.Domain/ExternalSaveWatch.cs`) : `SaveFileStamp(Path, Length, LastWriteUtc)` + `ExternalSaveWatch.Poll(stamp?)` → `NoChange | PendingStable | ChangedStable | Missing`. **Débounce à deux lectures identiques** : un fichier changé doit être relu identique une deuxième fois avant d'être parsé, donc un flush partiel en pleine écriture n'est jamais parsé. `Reset()` au changement de session. + `ExternalSavePublish.ShouldPublish(candidate, current, stamp, publishedStamp)` : un candidat null ne remplace jamais le dernier bon snapshot.
- Contrat : `IGameCompanionStore` gagne `External`, `UpdateExternal(...)`, `ClearExternal()` ; `GameCompanionStore` (App, ObservableObject) les implémente et `Stop()` clear aussi `External`.
- Côté App (`src/PKForge.App/Services/ExternalSaveMonitor.cs`, enregistré dans `MauiProgram`) : `PeriodicTimer` de **5 s**, actif uniquement entre `Start(romPath, emulator, label)` et `Stop()` — jamais de polling sans session externe. Résout le chemin via `ExternalSavePathResolver` (US-002), stat via `FileInfo`, décide via le Domain, puis `ISaveEngine.Validate` **avant** `OpenSession` + `ExternalCompanionSnapshotFactory.FromSession` (US-001), publie via `MainThread.BeginInvokeOnMainThread(() => UpdateExternal(...))`. Tout est try/catch : stat/read/parse en échec → on garde le dernier bon snapshot, aucun crash.
- Fichiers modifiés : `ExternalSaveWatch.cs` (nouveau), `GameCompanion.cs` (contrat), `GameCompanionStore.cs`, `ExternalSaveMonitor.cs` (nouveau), `MauiProgram.cs` (DI), `tests/.../ExternalSaveWatchTests.cs` (nouveau, 11 tests), `prd.json` (US-003 passes=true), `progress.txt`.
- **Apprentissages pour les itérations suivantes :**
  - Pattern « décision pure + I/O côté App » : le Domain reçoit des **stamps injectés** (`SaveFileStamp`) et décide ; l'App fait le `FileInfo`/read/parse. Toujours ce split pour tout polling (US-006 session timer suivra le même modèle).
  - Anti-flush-partiel : ne jamais parser sur un seul changement de mtime/taille — attendre 2 lectures identiques (débounce). Un `Validate(bytes)` avant `OpenSession` évite de parser une save tronquée.
  - Piège timer : `PeriodicTimer.WaitForNextTickAsync` lève `ObjectDisposedException` (pas `OperationCanceledException`) quand `Stop()` dispose le timer → attraper les deux silencieusement.
  - `Lock` (System.Threading.Lock, net9+) est le pattern de verrouillage déjà utilisé (`JsonConsoleEmulatorStore`) — réutiliser.
  - DI : enregistrer le service concret (`AddSingleton<Services.ExternalSaveMonitor>()`) pour que les vues puissent le résoudre directement.
  - US-004 devra appeler `ExternalSaveMonitor.Start(...)` au lancement externe et `.Stop()` au retour foreground (le `TrophyWatcherService` tourne déjà sur resume — même endroit).
